## O que cada um faz

**RAG** responde à pergunta: *"Que informação o agente precisa para responder?"*

**SRP** responde à pergunta: *"Que informação o agente tem permissão de alcançar?"*

São camadas complementares, não competitivas.

## The Layered Ecosystem

Para compreender o SRP, é fundamental entender onde ele se posiciona na stack moderna de agentes de inteligência artificial.

| Layer | Role | Failure Without SRP |
|---|---|---|
| RAG | Context retrieval | Sensitive retrieval contamination |
| MCP | Tool communication | Unsafe tool reachability |
| Harness | Agent execution | Unlimited architectural traversal |
| Guardrails | Output validation | Late-stage policy enforcement |
| **SRP** | **Traversal boundary enforcement** | **Prevents illegal context assembly** |

## Onde RAG é forte

RAG é excelente para:

- Encontrar informação relevante em grandes corpus
- Aumentar o conhecimento do modelo com dados específicos do domínio
- Reduzir alucinações com grounding factual
- Integrar com bases de conhecimento existentes

## Onde RAG não resolve

RAG recupera baseado em **relevância semântica**. Não distingue:

- Um ficheiro de configuração relevante que o agente *deveria* ver
- Um ficheiro de secrets igualmente relevante que o agente *não deveria* ver

Se `jwt-secrets.ts` é semanticamente similar à query "otimizar autenticação", RAG vai incluí-lo no contexto.

## Como funcionam juntos

```
Query do Agente
    │
    ▼
┌─────────┐     ┌─────────┐
│   SRP   │────▶│   RAG   │
│ Firewall│     │ Retrieval│
└─────────┘     └─────────┘
    │                │
    ▼                ▼
Scope filtrado   Contexto recuperado
    │                │
    └───────┬────────┘
            ▼
    Contexto seguro + relevante
```

SRP filtra **antes** do RAG. O RAG opera apenas sobre o subgrafo que o SRP autorizou. O resultado: contexto que é simultaneamente relevante e arquitecturalmente seguro.
