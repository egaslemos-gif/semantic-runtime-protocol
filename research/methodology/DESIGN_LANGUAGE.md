# Design Language

The visual philosophy of Runtime-Oriented Product Engineering communicates engineering seriousness, operational discipline, and infrastructure thinking.

It is explicitly NOT a consumer marketing site or a flashy startup landing page. 

## Visual Philosophy

The platform must feel like a tool built for engineers, by engineers. It should inspire confidence through density, structure, and precision.

**Inspirations:**
- Stripe Docs (Precision and clarity)
- Vercel (Minimalism and focus)
- Linear (Performance and density)
- Supabase (Developer-centric dark mode)

## Core Principles

### 1. Information Density over White Space
Engineers scan for answers. Do not force them to scroll past massive hero images or abstract illustrations. Text should be dense, legible, and structured hierarchically.

### 2. Monospace for Concepts
Code is our native language. Use monospace fonts not just for code blocks, but for system primitives, file paths, and architectural rules to visually distinguish them from narrative text.

### 3. Structural Color
Color is a functional tool, not a decorative one.
- **Errors/Forbidden:** Strict Red.
- **Success/Required:** Muted Green.
- **System/Architecture:** Neutral Blues/Grays.
- Avoid gradients unless they serve to highlight a specific architectural boundary.

### 4. Zero Flash
- **NO** scroll-jacking.
- **NO** delayed fade-in animations on text.
- **NO** trendy motion-heavy UI that distracts from the content.

## Typography
- **Primary:** Inter or similar geometric sans-serif for high legibility at small sizes.
- **Monospace:** Fira Code, JetBrains Mono, or Geist Mono.

## The Aesthetic of Infrastructure
The design should look like a terminal evolved into a modern graphical interface. It must look like it belongs in the same environment as VS Code, GitHub, and AWS.
